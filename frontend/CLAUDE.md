## Dual-mode filtering (filtering-2, merged 2026-06-25)
**Catalog:** filter change → `setPage(1)` + `fetchArticles()` immediately (400ms debounce on year). **Scopus:** filter change → amber "Filters changed" badge, refetch only on the next explicit search.

**PR #79, 2026-08-01:** the anon branch of `SearchPage.tsx` used two independently-widthed `mx-auto` containers (hero `max-w-screen-sm` vs. results `max-w-screen-lg`) — Filters visually detached from the search bar, and didn't render at all before `hasSearched`. Both modes now share one container (`mx-auto max-w-screen-xl px-4 py-6 flex flex-col gap-4`); `ArticleList` mounts unconditionally. General lesson: never add a second independently-centered container next to an existing one — different max-widths mean their left edges won't align.
**PR #82, 2026-08-03:** `ArticleFiltersSidebar`'s open/collapsed state is now a controlled prop (`open`/`onToggle`) owned by `SearchPage`, not local `useState` — `ArticleList` renders it from 3 different conditional JSX branches (skeleton/empty/results) and submitting a search switches branches, remounting the component and silently resetting local state. `MultiSelectCombobox` now sorts its options by the currently displayed (translated) label via `localeCompare(i18n.language)` — doc types/countries were ordered by relevance, not alphabetically. Countries: `constants/countries.ts` (`ALL_COUNTRIES`, 250 — ISO 3166-1 via `i18n-iso-countries`, replaces the old 80-country `SCOPUS_COUNTRIES`) is the single source for both modes — catalog still derives its *option list* from `stats.by_country`, but now translates any of the 250 correctly instead of only the old 80. The 80 previously-curated EN values are preserved verbatim (not the package's default names) — they're passed straight through into `AFFILCOUNTRY(...)` in `scopus_client.py` with no backend allowlist, and the package's default name is the formal/treaty one for several countries (Russia → Russian Federation, Turkey → Türkiye).

## Error UX — "No Signal" + black hole (PR #49 merged 2026-07-05; follow-up PR #50 merged 2026-07-05)
3-layer architecture: root `ErrorBoundary` (`main.tsx`, outside `<App/>` — catches ThemeProvider/StarFieldCanvas crashes) → `errorElement` on a pathless nested child route (not on the route holding `element:<RootLayout/>` — else a crash would replace the whole layout, header included) + a separate `path:'*'` → `NotFoundPage`/`RouteErrorPage` (`pages/error/`, shared `ErrorPanel`) → the pre-existing local `ErrorBoundary.tsx` around charts/lists. `api/client.ts`: the 5xx toast shows `X-Request-ID` with copy-to-clipboard (issue #48). "Report this issue" — mailto to `VITE_SUPPORT_EMAIL` + a breadcrumb of the last ~10 navigations (`utils/errorReport.ts`, `sessionStorage`).
`ErrorPanel` has no solid card in either theme: light — text directly on the page + a static line-art "broken orbit ring" SVG; dark — a soft radial glow (built on the `#0c1927` background) + viewfinder corner ticks (`border-blue-500/40`) instead of a fill, so the starfield/black hole stay visible through the panel.
Signature effect: `StarFieldCanvas` accepts an optional black hole (`stores/blackHoleStore.ts` + `hooks/useBlackHole.ts`, coordinates in `constants/blackHole.ts`) — a continuous (not discrete) gravitational lens for stars/meteors/the mouse cursor; math lives in pure, testable functions in `utils/blackHoleLensing.ts` (2-zone ellipse→photon-ring model, orbital rotation with a GR-style accelerate/freeze profile, cursor drift toward center that freezes integration inside the disk). Hole position: X is split (desktop ratio / fixed ratio `<768px`), Y/radius share one continuous clamp model (`utils/blackHoleGeometry.ts:resolveBlackHoleGeometry`, PR #59, see below) that replaced the old discrete 768px px-switch. Decorative nebula density around the hole is reduced on mobile (~-30%, asymmetric between the vortex and the independent second nebula) for Canvas 2D performance. Full spec with final parameters — `docs/frontend-ui/error-experience/spec.md` (local only, not in the repo).

**Adaptive geometry and mobile polish (PR #59, merged 2026-07-09, + 2 direct commits to main same day):** `resolveBlackHoleGeometry(w,h,xRatio,messageBottomPx,safeAreaBottomPx,vortexClearancePx?)` — one clamp formula for radius/Y across all resolutions (radius `clamp(MIN,DIAM_RATIO·diagonal/2,MAX)`; Y `clamp(floor,target,ceil)`, floor protects whichever is larger — the hole's disk or its decorative vortex — with 3-step degradation down to `null`). `useBlackHoleMessageAnchor` measures `ErrorPanel`'s bottom edge (mount/resize/orientationchange/i18n/fonts.ready) into `blackHoleStore`. Post-merge fix: `vortexClearancePx` applies **mobile only** (`isMobile` = same `MOBILE_BREAKPOINT_PX`) — otherwise on wide desktop screens (where the vortex is proportionally even bigger than on mobile) the clearance overrode the soft Y target and pinned the hole to the viewport bottom. `ErrorPanel`: the Go home/Explore collection button row is an equal-width pair (`flex-1 basis-0`) at ALL breakpoints, not just `<sm`; below `sm` it uses a short label (`exploreShort`) and never wraps to 2 rows. Also: a static viewport meta (`viewport-fit=cover`), `overflow-x:clip` on `html,body`, an explicit mobile-first breakpoint scale in `tailwind.config.ts`, and a burger menu `MobileNavSheet.tsx` (`<sm`, duplicates the header's right-hand group, shadcn `Sheet`, ≥44×44 touch target).

## URL architecture `/{lang}/{section}` (PR #60, merged 2026-07-10)
Locale is reflected in the URL across the whole site (`/en/…`, `/ru/…`, `/cnr/…`), not just client state — `LocaleLayout.tsx` (wraps `/:lang`) validates the segment (invalid → an honest 404, not a redirect) and syncs `i18n.changeLanguage`/`document.documentElement.lang` from the URL; `LanguageSwitcher` navigates via `swapLocaleInPath`, never `i18n.changeLanguage()` directly. Every internal link/navigation goes through `LocalizedLink`/`useLocalizedNavigate`/`useLocalizedPath` (`hooks/`), never a bare `Link`/`navigate(path)` — otherwise the language prefix is lost. The third i18next locale resource is still named `sr-Latn` (folder/`supportedLngs`/plural forms unchanged), but its URL segment and hreflang are `cnr` (ISO 639-3 — Montenegrin has been an official language distinct from Serbian since 2007); the `urlLangToI18n`/`i18nToUrlLang`/`urlLangToHreflang` maps in `utils/localeRouting.ts` deliberately diverge. Legacy bare paths (`/explore`, `/auth`, `/profile`, `/article/:id`, `/forgot-password` — already indexed by Google) redirect to `/en/...`: an edge 308 (`vercel.json` `redirects`) + a client-side `<Navigate>` fallback in `router.tsx` (Vite's dev server doesn't read `vercel.json`). `/auth/callback`/`/reset-password` stay outside the scheme permanently (the backend hardcodes these 2 URLs without a locale prefix, `app/routers/auth.py:112,187`). `HomePage.tsx` was split into `MainPage.tsx` (marketing) + `SearchPage.tsx` (search); `AboutPage`/`PrivacyPage`/`TermsPage` were added. Details and a bug found along the way — [[project-i18n-url-routing]].
